# 模型与策略契约

## 物理资产

原始资源固定于 `DDTRobot/Col_DIABLO_Issac_RL` 的提交 `590085a027fc9e20b1d7e976714cd195488b96b6`，使用 `resources/robots/diablo/urdf/diablo_asm.urdf`。

`model.py` 通过 MuJoCo 原生 URDF 导入器读取几何、质量、惯量和关节范围，增加浮动基座、地面、IMU 和六个力矩执行器。未修改磁盘上的原始 URDF 或网格。

总质量18.041006 kg来自原始资产；并非对实物称量。原资产是等效串联腿，**没有表示真实并联闭环与实际电机到连杆的传动关系**。官方 Webots 的闭环结构是后续机械核对的参考，本项目不将二者混称。

相对上游训练的明确变化：

- 仿真器改为 MuJoCo，PPO 改由 Stable-Baselines3 提供。
- 采用腿部 `[-0.5,1.0] rad` 的展开初始姿态；上游默认全零是折叠姿态。
- 保留位置PD、轮速度PD及60 N径向腿部支撑前馈的形式；增加了来自27 Nm／26 rad/s限制的保守线性扭矩包络。这些均是待标定假设。
- 在加载后用轮碰撞网格实际最低点设置离地5 mm的初始高度，不以包围球半径替代轮半径。
- 与上游配置一样关闭机器人自碰撞；保留身体、腿和轮对地面碰撞。身体触地或倾斜过大结束回合。
- 源URDF导入后关节阻尼设为0.05、armature设为0.01，地面/轮摩擦设为 `[0.8,0.005,0.0001]`；均未实机标定。

## 时钟与坐标

- 世界坐标：z向上，长度m，角度rad，角速度rad/s，力矩Nm。
- 机体系：沿用原始 `diablo_base_link`，x为前进指令方向。
- 物理步长2 ms，控制周期10 ms，动作在五个物理子步内保持。
- 所有任务阶段使用仿真时间；运行报告另记墙钟时间。
- 陀螺仪与加速度来自 MuJoCo site 传感器；重力方向通过角速度积分和接近重力模长时的加速度修正估计。策略不读取基座真值姿态或真值线速度。
- 奖励、终止和评估使用物理状态。这是训练监督，不是实机可用观测；未实现定位、建图或导航链路。

## 观测

每帧25维，float32：

| 切片 | 字段 | 缩放 |
|---|---|---|
| `0:3` | 机体系陀螺仪角速度 | ×0.25 |
| `3:6` | 估计的机体系单位重力向量 | ×1 |
| `6:9` | 前进速度、偏航角速度、参考机身高度 | ×10、×0.25、×5 |
| `9:13` | 左髋/左膝/右髋/右膝相对默认角度 | ×1 |
| `13:19` | 六个关节速度 | ×0.05 |
| `19:25` | 上一步已限幅的六维动作 | ×1 |

基础任务的偏航指令为0，参考高度由模型初始展开姿态确定。轮位置不作为输入。

五帧按“最旧→最新”拼接，**包含当前帧**，扁平后是125维。每个控制周期只更新一次；回合开始时五帧填入同一初始观测，上次动作清零。

SB3环境输入为 `[125]`，向量环境为 `[N,125]`。导出模型输入名为 `observation`，形状 `[N,125]`，没有额外 GRU hidden 输入。

## 动作

输出名 `action`，float32 `[N,6]`，确定性均值限幅到 `[-1,1]`。

```text
left_fake_hip_joint
left_fake_knee_joint
left_wheel_joint
right_fake_hip_joint
right_fake_knee_joint
right_wheel_joint
```

此顺序显式按关节名绑定，不使用导入文件顺序猜测。

默认关节位置：`[-0.5,1.0,0,-0.5,1.0,0] rad`。

腿部：`tau = kp*(q_default + 0.5*action - q) - kd*dq + radial_feedforward`，两侧髋/膝的kp分别15/18，kd分别0.3/0.2。

轮部：`tau = 0.3*(10*action - dq)`；是轮速度反馈，不能把动作直接当作轮位置或Nm。

腿的径向支撑前馈为60 N，通过0.14 m等长二连杆的长度Jacobian变成膝力矩。它只使用关节编码器，不使用仿真真值姿态。最终力矩受模型包络与MuJoCo执行器±27 Nm双重限制。

## 失败与复位

正常训练回合结束后允许复位，这是强化学习采样；日志保留结束原因。评估每个任务只计首个回合，不回合内复位、重试或挑选成功片段。

非有限动作在推进物理前拒绝。MuJoCo数值警告或非有限状态直接抛错，训练保存失败检查点后退出，不自动重启。

## 导出

`diablo export` 生成 ONNX（opset17）、TorchScript 和 `contract.json`，用同一批物理观测比较两种导出与原SB3策略的动作。

此契约是本项目新定义的 MuJoCo 策略接口；不兼容此前DIABLO Isaac Gym示例的双输入历史编码策略，也不兼容D1h的33维/8动作接口。`hardware_authorized=false` 始终保留。
