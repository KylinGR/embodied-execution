# 模型与策略契约（主分支物理基线）

## 权威来源

机器人几何、质量和惯量以原始仓库主分支为基线。原始仓库不自行重画 CAD，而是在内存中组合以下固定版本的公开资源：

- [DDTRobot/Col_DIABLO_Issac_RL](https://github.com/DDTRobot/Col_DIABLO_Issac_RL/tree/590085a027fc9e20b1d7e976714cd195488b96b6)
  - `resources/robots/diablo/urdf/diablo.urdf`：主体几何、质量、惯量和网格。
  - `resources/robots/diablo/urdf/diablo_asm.urdf`：回程支链的惯量和网格。
- [DDTRobot/diablo-sim-env](https://github.com/DDTRobot/diablo-sim-env/blob/3c9abbcaeb93911932b9c14777c4e75cc8c1470e/diablo_A1/protos/DiabloOriginal.proto)：串联髋膝、电机轴、连杆端点、回程支链和闭环关系。
- [DIABLO 论文](https://arxiv.org/html/2407.21500v1)：机构说明及 M1502D 电机公开参数。

锁定信息保存在 `diablo_training/upstream.lock.json`。模型源文件在安装时下载，不打包进本仓库。

本版本恢复了原始主分支的 CAD 质量和惯量分布：

- 不把 CAD 总质量缩放到官网整机的 `22.9 kg`；
- 不用 Webots 质心覆盖 CAD 的连杆惯性质心；
- 不改变上游网格、连杆长度、轮径或闭环锚点。

## 机构与物理参数

每侧有三个主动电机，并包含两个被动铰链和一个闭环约束。整机为六个主动电机、四个被动关节、两个 `connect` 闭环和浮动基座。编译后满足：

```text
nq=17, nv=16, nu=6, neq=2
```

| 参数 | 主分支物理基线 | 说明 |
|---|---:|---|
| 总质量 | `21.019506 kg` | CAD 质量加两根回程连杆；不是官网整机质量 |
| 主轮碰撞半径 | `0.1 m` | 保留 CAD 圆柱几何 |
| 主连杆长度 | `0.14 m` | 官方几何 |
| 平行支链基距 | `0.09 m` | 官方几何 |
| 默认健康站姿 | `[0.969324,-1.938616,0,0.969324,-1.938616,0] rad` | 髋、膝、轮依次为左、右 |
| 髋/膝位置增益 | `15 / 18` | 主分支 PD 基线 |
| 髋/膝阻尼 | `0.3 / 0.2` | 主分支 PD 基线 |
| 堵转力矩 | `17 Nm` | M1502D 公开参考 |
| 额定力矩 | `9.6 Nm` | 公开参考 |
| 空载转速 | `220 rpm`，约 `23.038 rad/s` | 公开参考 |
| 物理步长 | `0.002 s` | 五个子步对应一个控制周期 |
| 控制周期 | `0.01 s` | 100 Hz |
| 主动关节阻尼/armature | `0.05 / 0.01` | 仿真参数 |
| 被动关节阻尼 | `0.001` | 仿真参数 |
| 髋关节范围 | `±1.57 rad` | 仿真范围 |
| 膝关节范围 | `[-2.9,0.1] rad` | 仿真范围 |
| 地面摩擦 | `[0.8,0.005,0.0001]` | 未做实物标定 |

默认健康站姿在轮底接地时要求基座原点位于 `z=0.350 m`，整机外形高度约 `0.477859 m`，轮轴与整机质心前后偏差小于 `1 mm`。复位从 `z=0.355 m` 开始，保留 `5 mm` 轮地间隙。`0.491 m` 仅表示产品资料中的上部高度包络，不是训练高度指令。

底部四个爬行小滚轮没有独立碰撞体。机器人自碰撞关闭，身体、腿和轮仍与地形接触。该模型是公开 CAD 参考仿真，不是称重、电机零位、热模型或驱动器限流标定后的实机模型。

## 动作接口

动作接口保持不变：

```text
dtype = float32
shape = [N, 6]
range = [-1, 1]
```

动作顺序固定为：

```text
left_hip_motor, left_knee_motor, left_wheel_motor,
right_hip_motor, right_knee_motor, right_wheel_motor
```

当前 MJLab 执行器语义：

- 髋、膝使用位置执行器，默认位置加 `0.5a`，位置增益和阻尼恢复为主分支的 `15/18` 与 `0.3/0.2`。
- 轮动作表示目标轮速，正动作沿机体 `+x` 前进。
- 轮速由 PI、前馈、目标斜率、积分限幅和 `17 Nm` 力矩包络约束。
- CPU 控制仍保留主分支的归一化动作到电机力矩映射。

策略输出始终是归一化动作，不包含执行器控制代码。更换执行器或控制映射时必须开始新实验。

## Actor 输入

Actor 接口保持不变：

```text
dtype = float32
shape = [N, 125]
```

Actor 由五帧 25 维本体观测按最旧到最新拼接：

| 切片 | 内容 | 缩放 |
|---|---|---:|
| `0:3` | 机体系角速度 | `0.25` |
| `3:6` | 机体系投影重力 | `1` |
| `6:9` | 前进速度、偏航角速度、航向误差 | `[10,0.25,5]` |
| `9:13` | 左髋、左膝、右髋、右膝相对默认位置 | `1` |
| `13:19` | 六电机速度，轮速按前进方向统一符号 | `0.05` |
| `19:25` | 上一控制步的归一化动作 | `1` |

Critic 使用相同本体历史，并追加真实基体速度、基座高度、横向位置误差、世界横向速度、目标路径法向速度、地形扫描、地形法向和轮地接触。特权信息不进入 Actor，也不进入 ONNX。

## 类型和维度冻结

以下接口是当前仓库和检查点的硬约束：

```text
observation: float32[125]
action:      float32[6]
```

修改机器人质量、惯量、几何、默认姿态、执行器或观测语义后，不得强行加载旧检查点。`contract.json` 会同时记录模型源码哈希、来源提交、控制周期、动作顺序和物理接口信息。

本次恢复主分支物理模型会改变模型文件和基座目标高度，因此此前基于非主分支几何训练出的检查点不兼容。

## 地形与课程

- 平地课程使用 MuJoCo plane。
- 坡面、崎岖、障碍和综合课程使用 MJLab 高度场。
- 地形扫描只进入 Critic，不改变 Actor 的 125 维输入。
- 机器人碰撞层与地形碰撞层分离，避免机器人自碰撞。

## 导出

ONNX 接口保持：

```text
input:  float32[N,125]
output: float32[N,6]
```

导出只证明网络与当前观测/动作契约一致。文件必须保留以下边界：

```text
simulation_only=true
hardware_authorized=false
```

实机部署仍需另行完成电机零位、驱动限流、通信延迟、热模型、负载和安全标定。
